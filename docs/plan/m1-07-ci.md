# M1-07 — CI no GitHub Actions

**Marco:** 1.1.0 · **Depende de:** M1-04

## Objetivo
Criar um workflow que instala o workspace e builda o servidor em cada push e PR, e que roda `test`/`typecheck` quando eles existirem.

## Contexto mínimo
- Ainda não existe CI (`.github/` não existe).
- O `package.json` raiz tem os scripts `build`, `test`, `typecheck` e `lint`, usando `pnpm -r --if-present`.
- O servidor ainda tem erros de tipo (são corrigidos em M2-09). Por isso, nesta etapa o typecheck **não** bloqueia.

## Início
- M1-04 commitado.

## Meio
1. `.github/workflows/ci.yml`:
   - Gatilhos: `push` e `pull_request`.
   - Job `ci` em `ubuntu-latest`: `actions/checkout@v4`, `pnpm/action-setup@v4` (a versão vem do campo `packageManager`), `actions/setup-node@v4` com `node-version: 22` e `cache: pnpm`.
   - Passos: `pnpm install --frozen-lockfile`, `pnpm test`, `pnpm --filter @manga/server build`, e `pnpm typecheck` com `continue-on-error: true` e um comentário dizendo que vira obrigatório em M2-09.
2. Validar a sintaxe localmente: `npx --yes @action-validator/cli .github/workflows/ci.yml`. Se a ferramenta não estiver disponível, `python -c "import yaml,sys;yaml.safe_load(open(sys.argv[1]))" .github/workflows/ci.yml`.
3. Rodar os mesmos comandos localmente na raiz: `pnpm install --frozen-lockfile && pnpm test && pnpm --filter @manga/server build`.

## Fim
- O validador não acusa erro.
- Os comandos do passo 3 terminam com código 0.

## Arquivos
- Criar: `.github/workflows/ci.yml`

## Fora do escopo
Docker na CI. Build mobile na CI.

## Commit
